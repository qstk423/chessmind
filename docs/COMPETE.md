# ChessCouncil · 天津移动 Token 算力大赛冲奖手册

## 一句话定位

**ChessCouncil**：多模态棋局感知 + 异质多智能体分析与动态辩论 + Stockfish 引擎仲裁的实时国际象棋系统（赛道二 · AI 游戏 / 算法对抗）。

## 决赛展示：7 分钟介绍与演示，3 分钟答辩

**不演示一整局。** 完整对局耗时不可控，也不能集中体现创新。现场只需展示一次可验证的核心闭环：预设局面 → 三位分析师 → 分歧判断 → 辩论/引擎仲裁 → 模型调用日志；随后用快速 AI 对战走 2–4 个半回合，证明对弈可运行。

| 时间 | 内容 | 屏幕与操作 |
|---|---|---|
| 0:00–0:45 | 团队介绍、作品目标 | PPT；团队成员与分工按真实情况填写 |
| 0:45–1:30 | 成果简介、设计思路 | PPT；局面规则校验 → 多角色分析 → 分歧调度 → 引擎仲裁 |
| 1:30–3:15 | 核心现场演示 | 工具 → 展开「路演 / 开发 · 调用日志」→ 点「中心破局 Demo」；模型实测约 80 秒，现场预留 105 秒 |
| 3:15–4:10 | 解释结果 | 棋盘右侧看战术/战略/风险、争议提示、辩论与仲裁；说明路演预设在角色建议不同时会主动触发辩论，即使低于常规阈值 |
| 4:10–4:45 | 可运行对弈 | 工具 →「快速 AI 对战」；回到棋盘后只看 2–4 个半回合，点暂停；不是整局 |
| 4:45–5:35 | 可追溯证据 | 工具 →「刷新日志」；展示模型名、成败、耗时、Token 和本机时间，说明原始日志使用 UTC，二者是同一时刻 |
| 5:35–6:25 | 主要功能与创新点 | PPT；三角色分工、按分歧决定是否辩论、规则/引擎复核 |
| 6:25–7:00 | 局限与收束 | PPT；说明联机受现场网络影响，核心展示采用本机单机流程；留出切换与意外缓冲 |

若 Demo 超过 105 秒：停止等待，播放**同版本、同模型、同机录制**的备用演示片段，并展示录制对应的原始日志。不可把预录结果说成实时调用。若模型服务不可达，现场转为纯引擎对弈，同时明确说明模型链路当时不可用。

## 创新点（评委三句）

1. **异质 Agent**：战术 / 战略 / 风险职责互斥，不是同一 prompt 复制粘贴。  
2. **分歧驱动辩论**：常规模式按争议阈值触发；路演预设为确保流程可展示，在角色建议不同时主动触发，并在界面标明。
3. **引擎接地 + 仲裁**：事实来自 python-chess / Stockfish，LLM 不能瞎编局面。

## 现场操作顺序（与当前 UI 一致）

1. `python -m src.main`（或 `docker compose up`）→ 打开 http://127.0.0.1:8000/chess/；演示前确认模型状态与网络可用。
2. 底栏 **工具** → 展开 **路演 / 开发 · 调用日志** → 点 **中心破局 Demo**；页面自动回棋盘。
3. 等进度结束；棋盘右侧看三位分析师。若触发辩论，页面自动切到 **辩论**；讲解仲裁结果。若未触发，说明三方推荐趋同，不假称已辩论。
4. 如需复盘，棋盘右侧点 **赛后复盘**；Demo 是局面级分析，不等于已完成一整局。
5. 底栏 **工具** → **快速 AI 对战**；它会新开标准开局并关闭 Council。回棋盘观察 2–4 个半回合后点暂停。
6. 底栏 **工具** → **刷新日志**。管理员日志需预先设置 `ADMIN_TOKEN` 和浏览器口令；不要在投屏或录屏时展示口令。原始 `logs/llm_calls.jsonl` 的时间为 UTC，界面转换为本机时间。

## 录屏（提交用，3–5 分钟）

### 工具

macOS：**QuickTime Player → 文件 → 新建屏幕录制**（选浏览器窗口，系统音频按需）。

### 分镜口播稿

| 镜号 | 画面 | 口播要点 | 操作 |
|---|---|---|---|
| 1 | 首页品牌 + 模型 pill | 痛点三句：引擎不会讲 / LLM 会幻觉 / 多 AI 无仲裁 | 停留 5–8s |
| 2 | 工具 →「中心破局 Demo」→ 进度条 | 三角色分析；常规阈值与路演触发条件不同 | 等 Council 结束 |
| 3 | 侧栏「辩论」+ 争议度条 | 展示质询 / 答辩 / 仲裁结论 | 滚动辩论内容 |
| 4 | 赛后复盘（可选） | Demo 是局面分析，勿称完整对局复盘 | 棋盘右侧点赛后复盘 |
| 5 | 快速 AI 对战走几步 | 标准开局；此快捷入口关闭 Council 以提速 | 工具 → 快速 AI 对战 → 走 2–4 个半回合后暂停 |
| 6 | 调用证明 | 证明真实调用（模型名 / 耗时 / Token / 时间） | 工具 → 刷新日志 |
| 7 | （可选）识谱 | 多模态入口；失败可跳过 | 更多工具 → 拍照识谱 |

### 录制勾选

- [ ] 镜 1–3 辩论完整出现（勿从空棋盘硬讲辩论）  
- [ ] 镜 4 复盘有数据  
- [ ] 镜 5 至少 4 步自动走子  
- [ ] 镜 6 日志里能看到本次 Demo 的 agent 行  
- [ ] 导出 `logs/llm_calls.jsonl` 与视频一并提交  

## Token 切换（大赛发下来后）

编辑 `.env`（不要提交真实 Key）：

```ini
LLM_API_KEY=<天津移动下发>
LLM_BASE_URL=http://111.32.22.35:32592/mgate/v1
LLM_MODEL=glm-5.1
LLM_THINKING=disabled
VISION_MODEL=glm-4v-plus
```

重启服务后顶栏 pill 应显示 `glm-5.1`。人机对局 AI 与 AI vs AI 的大模型方均走该模型。  
> Base URL 填到 `/v1` 为止；邮件里的完整路径若带 `/chat/completions` 请去掉这段。

## 风险预案

| 风险 | 预案 |
|---|---|
| API 超时 | 取消勾选 Council，纯引擎对战仍可演示；播预录视频兜底 |
| 开局无辩论 | 用 **中心破局 Demo** 展示，不从标准初始局面硬等辩论；仍应如实说明触发情况 |
| 识谱失败 | 跳过 multimodal，强调 FEN 纠错 + Demo |
| 超时 | 缩短 Agent max_tokens；Demo 只跑一局；快速 AI 关掉 Council |
| 旧页面缓存 | 硬刷新；确认工具页显示「中心破局 Demo」 |
